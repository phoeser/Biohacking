FIRESTORE-REGELN FÜR DIE ERFAHRUNGSBERICHTE
===========================================

FERTIG AUSGEFÜLLT — du musst nichts mehr anpassen.
Der Block unten zwischen den Strichlinien wird komplett kopiert und in der
Firebase-Konsole eingefügt.

Der Admin wird über die verifizierte E-Mail-Adresse erkannt, nicht über die
UID. Grund: Das ist derselbe Wert, der auch in js/data/erfahrungen.js unter
ERFAHRUNG_ADMIN_EMAILS steht — eine Stelle weniger, an der etwas auseinander
laufen kann. Bei Google-Anmeldung ist email_verified immer true, deshalb ist
die Prüfung genauso belastbar wie eine UID.

SO GEHT ES (dauert zwei Minuten)
--------------------------------
1. https://console.firebase.google.com/project/biohacking-kompakt/firestore/rules
   öffnen.
2. Im Editor alles markieren (Strg+A) und löschen.
3. Den Block zwischen den Strichlinien komplett einfügen.
4. Oben rechts auf "Veröffentlichen" klicken.
5. Fertig. Ab dann siehst du in der App unter Erfahrungen den Kasten
   "Zur Prüfung", sobald jemand einen Bericht einreicht.

WICHTIG: Schritt 2 nicht überspringen. Die bestehenden MyData-Regeln sind im
Block unten bereits enthalten — wenn du den Block nur anhängst statt zu
ersetzen, hast du sie doppelt und Firestore lehnt das Speichern ab.

-------------------------------------------------------------------------
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // Wer darf Berichte freigeben? Muss mit ERFAHRUNG_ADMIN_EMAILS
    // in js/data/erfahrungen.js uebereinstimmen.
    function istAdmin() {
      return request.auth != null
             && request.auth.token.email_verified == true
             && request.auth.token.email == 'phoeser@web.de';
    }

    // ---- MyData: jeder sieht und schreibt nur seinen eigenen Bereich ----
    match /users/{uid}/{document=**} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }

    // ---- Erfahrungsberichte ----
    match /erfahrungen/{id} {

      // Oeffentlich lesbar sind nur freigegebene Berichte.
      // Angemeldete sehen zusaetzlich ihre eigenen Einreichungen,
      // der Admin sieht alles.
      allow read: if resource.data.status == 'approved'
                  || istAdmin()
                  || (request.auth != null && request.auth.uid == resource.data.uid);

      // Einreichen darf jede angemeldete Person — aber immer nur mit
      // status 'pending' und der eigenen uid. Das verhindert, dass jemand
      // sich selbst freischaltet.
      allow create: if request.auth != null
                    && request.resource.data.status == 'pending'
                    && request.resource.data.uid == request.auth.uid
                    && request.resource.data.substanz is string
                    && request.resource.data.substanz.size() > 0
                    && request.resource.data.substanz.size() <= 120
                    && request.resource.data.text is string
                    && request.resource.data.text.size() > 0
                    && request.resource.data.text.size() <= 4000;

      // Freigeben, ablehnen und loeschen darf nur der Admin.
      allow update, delete: if istAdmin();
    }
  }
}
-------------------------------------------------------------------------

FALLS DU SPÄTER LIEBER DIE UID VERWENDEN WILLST
Die UID ist unabhängig von der E-Mail-Adresse und damit langfristig stabiler.
Du findest sie unter
https://console.firebase.google.com/project/biohacking-kompakt/authentication/users
in der Spalte "Nutzer-UID". Dann istAdmin() so ersetzen:

    function istAdmin() {
      return request.auth != null && request.auth.uid == 'HIER_DIE_UID';
    }

TESTEN, OB ES WIRKT
In der Firebase-Konsole gibt es neben dem Regel-Editor den "Rules Playground".
Dort kannst du eine Leseabfrage auf /erfahrungen/beliebig simulieren, einmal
ohne Anmeldung und einmal mit deiner Adresse — ohne echte Daten anzufassen.

WAS PASSIERT, WENN DU NICHTS TUST
Ohne diese Regeln greifen die alten. Eingereichte Berichte werden dann
entweder gar nicht erst gespeichert oder bleiben unsichtbar liegen. Kaputt
geht nichts — die Funktion bleibt nur wirkungslos.
